# results — 评测证据（脱敏）

这些 JSON 是 `eval`/`bench`/`ablation` 的聚合输出，绝对路径已替换为 `<HOME>`，不含任何 API key。

- `ablation.json` — **R=3 配对消融**（4 配置 × 22 任务 × 3 轮），g01 判分收紧与安全整改**之后**的真实数据
- `bench.json` / `summary.sample.json` — 早期单次评测的聚合（**pre-fix**，保留仅供对照，数字不作结论）

## R=3 消融的诚实结论（重要）

四个配置全部落在噪声区间内（均值 97–98.5%、中位 95.5–100%），**g01 在所有配置里都是 flaky（含 baseline）**，
"关压缩"的 prompt token 与 baseline 几乎相同（7773→7761）。即：

> **在 R=3 配对下，没有任何一个机制呈现出可统计分辨的通过率提升；早期"护栏 +4.5%""压缩 −4% token"的单轮结论被本次重测证伪。**
> 唯一稳定、可复现的信号是：开放式任务 g01 的终止 flakiness 是当前套件的真实前沿，且现有护栏并不能可靠消除它。

这份"自我证伪"的数据被刻意保留在仓库里——它比一个好看的百分比更能说明评测是否诚实。
可信的机制效应需要更大 R 与逐任务配对（或更强的失败任务）才能测出。
